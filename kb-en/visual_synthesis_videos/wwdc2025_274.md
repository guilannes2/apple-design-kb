### What the images show
Basis: 21 of 21 frame sheets viewed, all codes checked.
- Agenda list used as a progress indicator at nearly every topic change: same vertical list, same order, current item in strong black and the rest in light gray (sheets 0001 q0007 to q0009, 0005 q0039 to q0041, 0009 q0073, 0013 q0116, 0017 q0149). The notes record that the talk does not comment on this feature, it exists only on screen.
- Code highlight via a translucent blue rectangle overlaid on the line under discussion, with no cursor or arrow, shifting from frame to frame: in sheet 0004 the highlight moves from the HStack's body, to the button block and then to the slider's (q0028 to q0030); in sheet 0020 it moves from the event signature to the animation block (q0173 and q0174).
- Code built up incrementally, in sequences of three to five nearly identical frames, rather than appearing complete: the robot's view grows block by block in sheet 0003 (q0022 to q0026) and the manipulation configuration call goes from one line to several named parameters in sheet 0010 (q0084 to q0086).
- A floating beige card next to the code listing, in pill capsules, the components that the call injects on its own, growing from three to four items between consecutive frames (sheet 0010, q0082 to q0084).
- Corner badges as an editorial layer: green circle with "NEW" marks a new API (sheets 0004 q0034 and q0035, 0012 q0100, 0014 q0118, 0017 q0151, 0019 q0165) and a green circle with a checkmark marks a code example considered correct (sheet 0016, q0137, q0138 and q0141). The notes point out that none of this is mentioned in the talk.
- A pair of images with and without the layout modifier, same camera and same setting, to isolate the variable: without it the robot is small, shifted to the right and with the plate cut off; with it, it is centered and larger (sheet 0006, q0048 and q0049).
- Three layout variations shown at the same time in the same scene, each robot inside a dashed box of its own color and with a red, green and blue axis gizmo at the base marking the origin; the camera orbits around between q0050 and q0055 and the boxes remain consistent (sheets 0006 and 0007).
- A diagram template reused for abstract concepts, always solid-colored rectangular boxes connected by arrows: a view-and-model pair next to a wireframe teapot (sheet 0002, q0016 to q0018), the entity, component and system architecture that only gains its third box once the talk reaches it (sheet 0007, q0062 and q0063), and the bidirectional flow between the two frameworks drawn as an orange box for SwiftUI and a purple one for RealityKit, connected by two labeled arrows pointing in opposite directions (sheet 0015, q0128).
- A cause-and-effect chain built box by box to explain the loop risk: modified state, view body evaluation and update closure appear in three successive frames (sheet 0015, q0131 to q0133), and the same diagram reappears next to an example whose own code comment warns of the cycle (q0134 and q0135). In sheet 0017 the remedy is drawn as two identical parallel columns with no connection between them (q0145).
- An API spec sheet presented as a vertical list of properties in monospaced font: the playback controller in sheet 0003 (q0027) and the observable structure with seven properties in sheet 0014 (q0120 and q0121).
- Interface controls drawn inside the 3D scene itself: a translucent rounded-corner panel with a label, animation selector, play button and a thin progress bar (sheet 0003, q0020 and q0021); an options popover with a checkmark next to the chosen item (sheet 0005, q0037); a circular minimap fixed in the top right corner functioning as a HUD (sheet 0014, q0122 to q0124).
- A 3D authoring tool shown inside a MacBook frame, with a dark properties panel and color wheel on the right and a light viewport on the left; across three frames the particle effect changes from a vertical jet to a directional fan and then to a radial explosion, showing adjustments made live (sheet 0007, q0059 to q0061).
- Physical interaction shown as a mixed-reality composite, with real hands in the photographed environment alongside the rendered object and never showing the device (sheet 0009, q0075); in sheet 0018 the same composite appears with the hand approaching the robot, which releases visible sparks (q0159).
- The two mascots carry distinct palettes and act as a throughline: a floating name plate above the green robot (sheet 0011, q0099), a greenhouse table with pink and green light rings on its top (sheet 0012, q0106) and a closing shot with the two robots in miniature on the presenters' real table (sheet 0020 q0180, sheet 0021 q0181).
Visual proportion: per the notes, most of the frames are code, slide, diagram or rendered 3D scene; presenters alone in close-up occupy short transition stretches (sheets 0009 q0079 and q0080, 0011 q0091 to q0093, 0013 q0109 and q0110, 0017 q0146 to q0148), and the final frame shows the two presenters with the miniature robots on the table (sheet 0021, q0181).
Recorded divergences or limits: two frames appear empty, with no visible content, treated as transitions (q0081 and q0111); one frame in sheet 0008 is cropped, with only half the list visible (q0071); and in sheet 0018 the two frames that should show the before and after of the toggle show the robot in the same central position (q0161 and q0162).
