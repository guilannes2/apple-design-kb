### What the images show
Basis: 20 of 20 frame sheets viewed, all codes checked.

- The screen convention is rigid across almost the entire video: code on the left in monospaced font with colored syntax, device frame on the right showing the result, always in that order (sheets 0002 to 0019). The iPhone is used for every interactive example, while a blank-screen iPad appears between code blocks as an editing pause, with no content (sheets 0012 to 0018).
- The most recent or most relevant code snippet is marked by a translucent light blue rectangle, and across several passages the text does not change between frames, only the highlight shifts from one token to another, guiding the eye through the explanation (sheet 0017, q0145 to q0149, passing through function name, maximum sample offset, color and position).
- Each block opens with a comment that functions as a section title within the code itself, for example rotation effect, parallax effect, visual effect modifier and a simple ripple effect (sheets 0003, 0004, 0005 and 0018).
- The video opens with an unannotated before-and-after pair: three same-size circular icons in a row, first gray and inert, then colored and animated, with a highlight ring on the microphone, smaller hearts bouncing above the filled heart and the star in a multicolor treatment (sheet 0001, q0005 to q0006).
- The circular carousel is shown as a geometric consequence, not as a generic effect: the code applies rotation proportional to the item's position in the scroll plus a vertical offset when the view is not fully on screen, and in the frames the two photo cards appear tilted in opposite directions, with the tilt varying according to position (sheet 0003, q0019 to q0027).
- The metaphor switch is recorded in the change of code and result: the same card starts shifting the image on the horizontal axis without moving the mask that crops it, inside a stack with width relative to the container and a rounded-corner rectangle crop, producing two slightly offset layers within the same card (sheet 0004, q0031 to q0036), and in the last frame a white text caption enters at the bottom left corner of the photo (sheet 0004, q0036).
- The visual effect modifier is demonstrated through direct contrast in the same list: shopping rectangles all purple and monotone in one frame, and in the next frame the same list with hue varying from purple to pink and red according to vertical position, calculated from the global frame's origin (sheet 0005, q0042 to q0044, with q0043 showing the block still without a body).
- Before presenting the new feature, the screen situates the existing color tooling on a single panel: three thumbnails of gradient types in a three-column grid, three horizontal bars for brightness, hue rotation and saturation with a label above each one, and eight small swatches of blend modes (sheet 0007).
- The mesh gradient is taught first as a diagram and only afterward as code: a three-by-three grid of points anchored at the corners and edges, joined by thin white lines, with smooth interpolated fill; in the next frame the center points are dragged, the mesh deforms and the fill becomes irregular patches with sharper transitions near the closest points, with a hollow white control point marking what is being dragged (sheet 0007, q0061 to q0062).
- The same idea reappears in code with the result alongside it, and the difference between two frames isolates the variable: when the center point's coordinate changes from the midpoint to a shifted value, the background on the iPhone goes from straight horizontal bands to an asymmetric diagonal shape (sheet 0008, q0067 to q0068).
- The custom transition is built up layer by layer on the same avatar: first the behavior with no transition, with the element simply appearing and disappearing, then scale, then scale combined with opacity, and then its own struct that adds scale, opacity, blur, a full-turn rotation with a sign depending on direction and an extra glow on entry (sheets 0009 q0079 to q0081, 0010 q0082 to q0090, 0011 q0091 to q0093). In one frame the next line appears dimmed as a preview of the next edit before it settles into normal opacity (sheet 0011, q0092).
- The text's internal hierarchy gets an exclusive diagram in the batch: nested blue boxes drawn over the blurred code, with the outer layout box containing the line, and the line containing a row of runs and run slices with an ellipsis indicating continuity (sheet 0014, q0125). In the next frame the diagram disappears and the code returns legible with the function signature changed (sheet 0014, q0126).
- The text renderer is built in successive blocks without rewriting what already existed: first the minimal version that only draws each line, then three timing properties, then the conformance that links elapsed time to the animatable data, and further on the progress calculation, opacity via entry curve, blur radius derived from the line's typographic height and vertical translation by spring from the line's descender (sheets 0012 q0106 to q0108, 0013 q0112 to q0116). A gray footer bar cites an earlier session as a cross-reference (sheet 0012).
- The decision to emphasize only one excerpt appears in the example code and in the conditional check: the marked expression gets a custom attribute, pink color and bold, and in the drawing the alternate branch applies a short fade to the rest of the text, with that branch highlighted in blue in the last frame (sheet 0015, q0132 to q0135).
- The debug interface is shown as a real product, overlaid on the example: at the top of the iPhone screen, four sliders labeled time, amplitude, frequency and decay, each with a white circular handle over a thin gray track, and the example photo occupying the rest of the card. Between two frames the handle of one of the sliders changes position, recording the manual adjustment, and the code alongside it carries a good-humored comment admitting that the values have not been found yet (sheet 0019, q0166 to q0168).

Visual proportion: by the notes, the overwhelming majority of frames are code with a device mockup, topic slide or illustration, with the two presenters appearing interspersed between blocks, and the topic list reappearing as a progress marker with no narration explaining it (sheets 0001, 0006, 0009, 0011, 0016 and 0017).
Recorded divergences or limits: since these are still frames, several animations do not actually appear. The transition blur is not visually demonstrated in the frames where it is added to the code (sheet 0010, q0088 to q0090), the text preview remains identical in the three frames where it appears (sheet 0013), and the photo used in the ripple effect stays static in every frame (sheet 0018). The notes also flag as uncertain a set of abstract interface elements with no clear before-and-after pair (sheet 0006, q0049 to q0051), a frame with only a plus icon at the center treated as a probable scene cut (sheet 0009, q0076), a frame with two overlapping, illegible code states in a crossfade (sheet 0002, q0017), and the blank iPad interpreted as an editing device, not as an interface example.
